## 0. 方法论（skill 流程在本项目的落地）

| 阶段 | 内容 | 检查点 |

## 1. 技术栈决策（对《前端规范.md》的现实修正）

| 项 | 原规范 | 本规划（修正） | 理由 |
|---|---|---|---|
| 框架 | Vue 3 + Vite | **Vue 3 + Vite**（不变） | 已定，生态成熟 |
| 地图底图 | MapLibre GL（容东离线瓦片） | **无底图模式**：直接渲染路网 GeoJSON 矢量 | **我们没有容东离线瓦片资源**；答辩投影（10m 观看距离）下暗色矢量路网 + 车辆动效比真实地图更醒目、零外部依赖 |
| 车辆/信号渲染 | deck.gl（3000+ 辆） | **自研 Canvas 2D 渲染层** | base_network 仅 ~100-300 辆车，Canvas 足够；自研层可完全控制视觉（信号相位光环、排队热力渐变、事故脉冲动画），设计感远超 deck.gl 默认样式，且免去 deck.gl+Vue 集成复杂度 |
| 图表 | ECharts | **ECharts**（不变） | 指标曲线/对比图 |
| 通信 | 原生 WS + Fetch | **原生 WS + Fetch + Pinia**（状态管理） | 数据流清晰 |
| 样式 | — | **手写 CSS + CSS 变量 token**（不用 Tailwind） | 契合 skill 的"先声明设计系统"工作流 |

> 修正依据（skill Step 0 事实核验）：项目未含离线瓦片；车辆规模由路网决定（20 路口/80 边，实测在网 50-100 辆）。这两点修正降低依赖面、提升视觉可控性，答辩更稳。

## 2. Design Read（设计判断 + 五拨盘）

```yaml
Design Read:
  artifact: 车路云协同管控 Dashboard（答辩演示单页）
  audience: 评委（专家/行业，10m 投影）+ 答辩人（操作者）
  visual-language: 指挥中心数据面板（deep command center），而非 SaaS 官网
  mode: greenfield（全新）
  visual-variance: 6/10      # 允许有记忆点的布局，但以可读性为先
  motion-intensity: 6/10     # 车辆流动/相位切换/Agent 思考态有动效，克制不炫技
  information-density: 7/10  # 一屏容纳 6 大面板，密度高但分区清晰
  asset-dependence: 3/10     # 不依赖真实图片素材（无品牌资产约束，图形全自绘）
  brand-fidelity: 4/10       # "雄安/车路云"叙事用色彩语言表达，非 logo
```

四问自答（skill Step 3a）：
- **叙事角色**：路网画布是 Hero（视觉主角），Agent 对话是互动焦点，指标/对比是证据；
- **观看距离**：10m 投影 → 正文 ≥ 24px、关键数字 ≥ 48px；
- **视觉温度**：权威 + 科技 + 略有人文（避免纯冷工业感）；
- **容量检查**：1920×1080 下六区布局（顶栏/画布/右对话/左面板/底对比）不溢出。

## 3. 设计方向（3 选 1，Checkpoint 1）

> skill 要求三个方向来自**不同学派**，保证选择有意义。每个方向含：参考、契合理由、视觉特征。

### 方向 A · 信息架构派（Tufte/Pentagram 数据理性）
- **参考**：Edward Tufte 数据墨水理论、Bloomberg Terminal、Pentagram 信息设计
- **契合**：本项目本质是"科学评估平台"——评委最看重数据的可信度；该方向把"对比实验、指标量化"的气质做到极致，最像严谨的工程成果
- **视觉特征**：克制浅色或中灰底；**极高数据墨水比**（去网格线、去装饰）；等宽字体数字；图表是主角；色板仅蓝/橙两色语义编码（好/差）
- **代表作**：Bloomberg Terminal 的密度与秩序

### 方向 B · 现代 AI 指挥中心（Linear/Vercel 深色工具美学）
- **参考**：Linear、Vercel、Raycast
- **契合**：本项目故事线是"AI 控灯 + LLM Agent"——深色指挥中心最贴合"城市大脑"叙事，答辩投影（暗环境）下对比度最高、最抓眼；发丝线 + 单一强调色 + 等宽 chips 是 AI 工具标配语言
- **视觉特征**：暖深色底（近黑偏暖，非 #0D1117 纯 GitHub 黑）；**单一强调色**（可选：信号灯绿/琥珀/青蓝）；发丝分隔线；等宽字体用于路口 ID/参数；信号相位用发光圆点；Agent 消息用精致气泡
- **代表作**：Linear 的克制与精致

### 方向 C · 雄安蓝绿人文派（自定义：未来之城 + 生态底色）
- **参考**：雄安新区"蓝绿交织、清新明亮"规划理念 + Aesop/无印良品的留白克制
- **契合**：评委看到"雄安元素"会天然加分（赛题强调雄安特色场景）；青蓝（白洋淀水）+ 浅绿（生态）是雄安官方视觉语言
- **视觉特征**：浅色为主、青蓝/浅绿双主色（水色系渐变仅用于区域底纹，不用于按钮渐变）；留白充足；圆角温和；字体偏人文（思源黑体类）
- **代表作**：雄安新区官方视觉体系 + MUJI 的安静

> **推荐**：方向 B（答辩投影效果 + "城市大脑"叙事最契合 + 深色对暗色信号灯/热力渲染最友好）。但如果你希望评委看"严谨评估"气质更重 → A；想突出雄安叙事 → C。

## 4. 页面结构与组件树（无论选哪个方向都适用）

单页 Dashboard（《前端设计建议.md》§2 布局），P0 元件先行：

```
App.vue
├── TopBar                   仿真控制条：启动/停止/暂停/倍速/步进 + 路网选择 + LLM 状态
├── NetCanvas                 主区画布（Canvas 2D 渲染层）
│   ├── useNetRenderer        GeoJSON 路网 → 边/节点绘制（矢量，无底图）
│   ├── useVehicleLayer       WS vehicle_update 增量 → 车辆圆点+轨迹尾迹
│   ├── useTlsLayer           tls_update → 信号相位发光圆点（G/y/r）
│   ├── useQueueHeat          edge 排队 → 边着色热力
│   └── useEventLayer         事件标记 + 注入动画
├── AgentPanel                右侧对话（高度 > 700px 常驻）
│   ├── ChatMessages          用户/助手气泡（Markdown 渲染）
│   ├── ToolCallLog           工具调用回放（可折叠：tool/args/result）
│   ├── QuickPrompts          三场景快捷指令 chips
│   └── TypingIndicator       "Agent 正在分析态势…"加载态
├── MetricsPanel              左侧：指标卡（veh/speed/wait/queue）+ ECharts 时间序列
├── SchemePanel               方案切换 + MAPPO/SCOOT 模式 + 参数滑块（min/max_green…）
├── EventPanel                事件注入（事故/施工/车流）+ 事件日志
└── CompareSection            底部：三方案 vs 固定配时 ECharts 曲线 + 汇总表
```

状态管理（Pinia）：`simStore` / `metricsStore` / `agentStore` / `eventStore`；
数据接入：REST（`/api/v1/*`）+ WS（`/ws`，增量渲染 + 视域裁剪可选）。

## 5. 实现里程碑

| 里程碑 | 内容 | 出口标准 |
|---|---|---|
| M0 设计确认 | 选定方向 → 输出设计系统 token（色板/字体/间距/圆角/阴影/动效） | 用户确认（Checkpoint 1） |
| M1 v0 草案 | 静态骨架 + token + 占位符，可看不可点 | 用户纠偏（Checkpoint 2） |
| M2 画布渲染层 | GeoJSON 路网 + 车辆/信号/热力 Canvas 渲染 | 真实路网可见、车辆流动 |
| M3 数据接入 | REST + WS 实时化 + 顶栏控制条全功能 | 能启动/停止/倍速仿真 |
| M4 Agent 面板 | 对话 + 工具回放 + 快捷指令 + 加载态 | 真实对话全流程 |
| M5 打磨交付 | 指标/对比图表 + 状态覆盖 + 五维评审 + 预交付检查 | 通过评审清单 |

> 预计 M1 半天、M2-M3 各 1 天、M4 1 天、M5 半天（单人全力约 4 个工作日）。
