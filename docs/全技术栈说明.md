# 车路云协同管控平台 · 全技术栈说明（零基础版）

> 这份文档假设你**完全没接触过**这个项目，甚至没写过代码。我们从"这个项目是什么"讲起，一直讲到"每一行代码在干嘛、怎么改"。看完你能跑起来、能看懂、能上手改。

## 第 1 章 这个项目是干什么的

一句话：**在电脑里模拟一座城市的红绿灯和车流，然后用"AI 算法 + 大语言模型"自动指挥交通，最后能一键生成评估报告。**

具体做了四件事：
1. **仿真**：用 SUMO（德国开发的微观交通仿真软件）在电脑里跑一个真实的城市路网（雄安容东 20 个路口），里面有车、有红绿灯、有拥堵；
2. **智能控制**：写了三个控制"算法"来指挥红绿灯/车辆：
   - 方案一：固定配时 + 绿波（红绿灯按时间表走，主干道绿灯连成波浪）
   - 方案二：MAPPO 强化学习（AI 每 5 秒看一眼路口情况，决定绿灯延长还是切换）+ SCOOT 兜底
   - 方案三：车端引导（给"特殊车队"实时规划最优路线，避开拥堵）
3. **大模型指挥**：接入了 LLM（智谱免费 API 或本地 Ollama），你可以用**中文自然语言**下指令，比如"东侧拥堵，调整最长绿灯"——智能体会自动调用工具去执行；
4. **评估与报告**：把运行数据算成评分（效率×稳定×公平），还能导出一份图文并茂的报告（Word/PDF/Markdown）。

## 第 2 章 整体架构：三明治结构

```
┌─────────────────────────────────────────────┐
│  前端（浏览器页面）                            │
│  Vue 3 + Vite + Canvas 画布 + ECharts 图表    │
│  端口 5173                                   │
└──────────────┬──────────────────────────────┘
               │ HTTP 请求（REST） / WebSocket（实时推送）
┌──────────────▼──────────────────────────────┐
│  后端（指挥中心）                              │
│  FastAPI（Python）                           │
│  端口 8000                                   │
│  职责：启动/暂停仿真、算指标、跑算法、调 LLM     │
└──────────────┬──────────────────────────────┘
               │ TraCI（SUMO 的 Python 控制接口）
┌──────────────▼──────────────────────────────┐
│  SUMO 仿真引擎（交通世界）                     │
│  读路网文件 .net.xml，按步推进仿真             │
└─────────────────────────────────────────────┘
```

**数据怎么流动（一次完整演示）**：
1. 你在页面点"启动仿真"；
2. 前端把路网、方案发给后端；
3. 后端启动 SUMO，每 1 秒推进一步；
4. 每一步后端从 SUMO 读出"每辆车在哪、多快、每个路口堵不堵"；
5. 后端把这些数据通过 WebSocket 推给前端；
6. 前端在 Canvas 上画出车辆移动、红绿灯颜色、拥堵变色；
7. 如果你开了"方案二"，后端的 MAPPO 算法每 5 步做一个决策：这路口绿灯是延长还是切换；
8. 运行一段时间后，底部显示评分曲线，你点"生成报告"就能下载 Word/PDF。

### 3.3 最复杂的文件：NetCanvas.vue（画布）

这个文件约 1000 行，是整个前端的心脏。它做这些事：

- **坐标系转换**：SUMO 的世界坐标是"x 向东、y 向北"，屏幕坐标是"x 向右、y 向下"。代码里 `X(x) = x*scale + tx`、`Y(y) = -y*scale + ty` 做了翻转，所以地图上北在上；
- **真实车道**：后端给每一条边的每条车道返回真实几何坐标（`lane_shapes`），画布直接画这些折线，双向道路自动分开、路口处截断；
- **红绿灯**：后端每步推来每个路口的相位字符（如 `GGgrrr`），画布在每条进口道画对应颜色的小圆灯；
- **车辆动画**：每辆车有两个位置（上一帧/当前帧），画布按时间插值，让车辆平滑移动而不是跳帧；
- **点击交互**：点击车辆→显示路线和详情；点击道路→显示流量/速度/排队，还能"在此边添加车流"；点击路口→显示排队/相位。

### 3.4 数据怎么进前端

`realtime.js` 维护一个 WebSocket 连接到 `ws://localhost:8000/ws`，后端每秒推几种消息：
- `vehicle_update`：新增/移动/消失的车辆
- `tls_update`：红绿灯状态变化
- `metrics_update`：全局指标（每 60 步）
- `simulation_step`：步数、车辆数、平均速度（每步）
- `simulation_event`：事件通知

组件通过 `subscribe('vehicle_update', fn)` 订阅，收到数据就更新画布。

### 4.3 核心概念逐个讲

**TraCI 是什么**：SUMO 仿真跑起来后是一个"黑盒"，TraCI 像遥控器——`traci.vehicle.getSpeed("veh_1")` 问"这辆车多快"，`traci.trafficlight.setPhase("1", 3)` 命令"路口 1 切到相位 3"。`app/core/engine.py` 把所有 TraCI 调用封装成业务方法（`get_vehicle_state`、`set_tls_phase`…），项目其他模块只跟 engine 打交道，不直接碰 TraCI。

**仿真会话（session.py）**：启动仿真 = 创建一个线程，每步执行 `engine.step()`（SUMO 前进 1 秒）。状态机：`idle → running ⇄ paused → idle`。停止时关闭 SUMO、清空所有状态。

**数据采集（datacollector.py）**：每步做三件事：
- 对比"上一步的车辆"和"这一步的车辆"，算出新增/移动/消失的增量（避免每次都全量发几百辆车）；
- 全局指标每 60 步算一次（一个信号周期约 42 秒，评价按周期粒度）；
- 路口指标每步算（排队、平均等待、通过数）。

**运行时总管（runtime.py）**：一个 `AppRuntime` 对象串起所有模块——持有会话、采集器、算法、事件注入器、指标库、LLM 记忆。所有 API 接口都通过它干活。

### 4.4 三个控制算法怎么工作

**方案一（scheme_1）**：经典交通工程。TOD（时段表）决定现在该用哪套配时；Webster 公式按各进口流量算最佳周期和绿信比；MAXBAND 把主干道串联起来，让绿灯"波浪式"通过。每 300 步重算一次。

**方案二（scheme_2）**：AI 方案。每 5 步，用 `StateEncoder` 把路口及邻居的排队/相位编码成状态向量 → 送给 MAPPO 的 Actor 网络 → 输出动作（KEEP 延长绿灯 / ADVANCE 切换相位）。没有 PyTorch 时自动降级为 SCOOT（饱和度比规则）。STGCN 图卷积网络预测未来流量给奖励函数用。

**方案三（scheme_3）**：不管红绿灯，管车辆。维护一张路网图（边=道路，权重=实时旅行时间），为注册的车队车辆用 Dijkstra 算最优路径，周期性重路由避开拥堵，支持限行区域。

### 4.5 标准化算法接口（app/algorithms/，MCP 风格）

这是"算法即插即用"的机制，模仿 MCP（Model Context Protocol）的"工具发现"模式：

- **算法侧**：每个算法声明自己的"参数/观测/指标/能力"（`AlgorithmSpec`）。比如方案二声明参数 `min_green`（范围 0~20）、`mode`（枚举 mappo/scoot/auto），观测要 `avg_queue`、`tls_queues` 等；
- **框架侧**：`adapter.py` 按声明统一做参数校验（超范围拒绝）、统一采集观测、统一暴露状态；
- **前端侧**：统一 REST 接口——
  - `GET /algorithms` 列出所有算法
  - `GET /algorithms/{id}` 看声明
  - `GET /algorithms/{id}/state` 看实时观测和内部指标
  - `POST /algorithms/{id}/config` 设参数
  - `POST /algorithms/{id}/action` 触发动作

好处：以后加第四个算法，只需要写算法逻辑 + 一份声明，前端表单、参数校验、Agent 调用全部自动支持。

### 4.6 LLM 智能体（app/agent/）

**两级架构**：LLM 负责"高层决策"（看态势 → 决定调哪个工具），MAPPO/SCOOT 负责"低层执行"（路口级实时控制）。

**文本 JSON 协议**：为了让免费小模型也能用，不依赖 OpenAI 的 function calling，而是让模型直接输出 `{"tool": "工具名", "args": {...}}` 这种 JSON 文本，后端解析执行，把结果回填再让它继续——最多 8 步。

**14 个工具**（`GET /agent/tools` 可查）：查全局状态、查路口/道路、路径规划、事件注入、算法配置/动作、拓扑、区域状态、调控前后对比、生成报告等。所有工具都有参数白名单校验（安全护栏）。

**会话记忆**：后端保留最近 80 条对话消息，你可以说"刚才调过 E 走廊的绿灯"这种话，它能记得。

**模型切换**：前端下拉可切换 `glm-4-flash` / `glm-4.7-flash`（智谱免费）或 Ollama 本地模型，运行时生效。

## 第 5 章 关键流程图解

### 5.1 启动一次仿真

```
前端点击"启动仿真"
  → POST /api/v1/simulate/start {net_path, scheme, routes...}
  → runtime.start()
      → engine.connect(路网, 车流)   # 拉起 SUMO
      → Session.start()              # 起一个线程，开始推步
      → 算法 init()                  # 方案一算配时 / 方案二加载权重
  → 前端收到 session_id，开始收 WebSocket 数据
  → 画布 GET /network 拿到路网 GeoJSON，画路网
  → 每秒收到 vehicle_update，画车辆
```

### 5.2 一个"完整评估"流程

```
启动方案二跑 600 秒
  → 每 60 步算一次全局指标（平均速度/等待/排队/吞吐）
  → 每步推给前端；前端底部曲线逐点画出
  → POST /api/v1/evaluate/score  算出综合评分
      = 效率^0.5 × 稳定^0.3 × 公平^0.2
      硬性筛选：LOS F / 完成率<60% / 等待>4周期 则一票否决
  → 前端"生成报告"：选择格式/时间区间/内容
  → 后端汇总历史数据 + matplotlib 画 4 张图
  → 生成 .md / .docx / .pdf 下载
```

### 5.3 LLM 智能体做一次"应急调控"

```
用户："东侧拥堵，请调整最长绿灯，对比效果"
  → POST /agent/chat
  → 后端组装 messages（系统提示词 + 会话记忆 + 用户话）
  → LLM 输出 {"tool":"compare_metrics","args":{"action":"set"}}   # 先记基线
  → 执行工具，结果回填
  → LLM 输出 {"tool":"configure_algorithm","args":{"algorithm_id":"scheme_2","params":{"max_green":40}}}
  → 执行（参数校验通过 → 应用到方案二）
  → LLM 输出 {"tool":"compare_metrics","args":{"action":"compare"}}  # 对比
  → LLM 输出中文总结："平均速度由 1.1 提升到 1.6 m/s"
  → 前端聊天窗显示总结 + 工具调用记录（可展开看细节）
```

## 第 6 章 我怎么上手改？

### 6.1 想改前端界面

- 改页面布局 → `App.vue`；
- 改画布（路网/车辆/交互）→ `NetCanvas.vue`（改动前先理解坐标变换和 draw 函数）；
- 改顶栏/指标/事件/智能体 → 对应组件文件；
- 改颜色主题 → `src/styles/`（CSS 变量，`--accent`、`--bg-panel` 等）。

### 6.2 想加一个后端接口

1. 在 `app/api/` 下建一个 `router`（参考 `metrics.py`，很薄）；
2. 逻辑写在 `runtime.py` 或对应模块；
3. 在 `main.py` 里 `app.include_router(...)` 注册；
4. 前端在 `api/http.js` 基础上调用：`apiGet('/你的路径')`。

### 6.3 想加第四个控制算法

1. 建 `app/schemes/scheme4/`，写一个类继承 `BaseScheme`，实现 `init/on_step/handle_action/cleanup`；
2. 用 `@register_scheme` 注册，`name = "scheme_4"`；
3. 加一份 `algorithm_spec` 声明（参数/观测/指标/能力）；
4. 前端顶栏方案下拉自动出现"方案四"；
5. 想要 LLM 能调它，在 `agent/tools.py` 的算法工具里直接可用（`configure_algorithm` 传 `scheme_4`）。

### 6.4 想训练自己的 MAPPO

参考 `docs/MAPPO训练与验证指南.md`。要点：`app/schemes/scheme2/` 下有 `mappo.py`（网络）、`reward.py`（奖励）、`encoder.py`（状态）、`recorder.py`（数据记录）；训练脚本在项目 scripts 目录（见文档），训练出的权重放 `models/weights/`。

### 6.5 想换一个 LLM

1. 改 `backend/.env`：`LLM_PROVIDER`（zhipu/ollama）、`LLM_API_KEY`；
2. 智谱免费模型：`glm-4-flash`、`glm-4.7-flash`（前端下拉可直接切）；
3. 任意 OpenAI 兼容服务：设 `LLM_BASE_URL` + `LLM_MODEL`。

## 第 8 章 常见问题排查

**Q：双击一键启动后浏览器打不开？**
A：等两个黑色窗口都出现（后端 + 前端），手动访问 `http://localhost:5173`。

**Q：后端窗口报 SUMO 相关错误？**
A：检查 `SUMO_HOME` 环境变量是否指向 SUMO 安装目录（如 `E:\`），重启电脑或重新登录生效。

**Q：页面能开但画布一直显示"请先启动仿真"？**
A：正常。选一个路网 + 方案，点"启动仿真"。

**Q：智能体说"LLM 调用失败"？**
A：检查 `.env` 密钥；如果是 `glm-4.7-flash`，可能智谱临时限流，切回 `glm-4-flash`。

**Q：评分一直"硬性筛选未通过"？**
A：说明路网很堵（等待超 80 秒或完成率低于 60%），这是评分保护机制。可换车流少的路网或调整配时。

**Q：报告里没有图？**
A：报告图表需要仿真有足够历史数据（至少跑过几十步）；时间区间要覆盖有数据的步数。

**Q：端口 5173 被占用？**
A：任务管理器结束占用进程，或改 `start.bat` 里的 `npm run dev -- --port 5174` 并访问新端口。
