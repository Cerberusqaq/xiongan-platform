# 前端设计建议文档（展示项目亮点）

> 目标读者：前端负责人 / 答辩演示团队。本文档回答"**做哪些页面、哪些元件、按什么顺序做，才能把项目亮点讲清楚**"。
> 技术选型与数据契约见《前端规范.md》；演示剧本见《演示方案.md》；接口细节见《接口文档.md》。
> 核心原则：**所有数据来自后端真实 API / WebSocket，禁止假数据**——这是本项目的最大卖点（AI 真的在控灯、Agent 真的在调参）。

---

## 1. 展示什么（项目亮点 → 前端元件映射）

| 项目亮点 | 用哪个元件展示 |
|---|---|
| 车路云协同（云-边-端） | 路网可视化画布 + 方案管理面板（三方案切换） |
| **LLM Agent 智能体（赛道 C 补充要求）** | **Agent 对话面板**（对话框 + 工具调用回放） |
| MAPPO 强化学习信号控制（修复后可用） | 信号灯图层（相位实时变化）+ 方案对比图表 |
| 路网无关模型（不重新训练也能换路网） | 路网选择器（内置多路网 + 上传自定义路网） |
| 扰动事件应急响应 | 事件注入面板 + 事件日志 + 与 Agent 联动 |
| 轻量化部署（ONNX 边缘推理） | 模型部署信息卡（推理时延 / 一致率 / 模型体积） |

---

## 2. 总体布局：单页 Dashboard（答辩最稳）

答辩现场建议 **一个页面讲完**，避免切换页面丢节奏。推荐 1920×1080 布局：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：平台名 | 仿真控制条(启动/停止/暂停/倍速/步进) | 当前路网 | LLM状态 │
├────────────────────────────────┬─────────────────────────────────────┤
│                                │  C. LLM Agent 对话面板（右栏）        │
│  B. 路网可视化画布（主区最大）   │     · 对话框 + 快捷指令 chips         │
│     · 车辆层（增量动画）        │     · 工具调用回放（可折叠）           │
│     · 信号灯层（相位着色）      │     · "Agent 思考中"加载态            │
│     · 排队热力 / 拥堵蔓延       │                                     │
│     · 事件标记（事故/施工图标）  │  E. 方案管理面板                      │
│     · 点击路口→详情卡          │     · 三方案切换                      │
│                                │     · MAPPO/SCOOT 模式 + 参数滑块     │
├────────────────────────────────┴─────────────────────────────────────┤
│ 底部左：D. 实时指标卡片(车辆/速度/等待/排队)   |  F. 事件注入+日志        │
│ 底部右：G. 对比图表（MAPPO/SCOOT/固定配时 实时曲线 + 汇总报告）          │
└──────────────────────────────────────────────────────────────────────┘
```

> 可选第二页：**效果对比报告页**（三方案 vs 基线的柱状图/表格，放答辩 PPT 或视频分镜）。
> 可选模态框：**模型部署信息**（ONNX 推理时延、int8 体积、agnostic 路网无关说明）。

## 3. 元件规格（逐个说明）

### A. 顶栏 · 仿真控制条（P0）

| 项 | 说明 |
|---|---|
| 作用 | 演示第一步"启动仿真"，也是评委上手第一眼 |
| 元件 | 开始 / 停止 / 暂停 / 恢复 / 倍速(1×/2×/5×) / 步进；当前路网名、仿真步数、仿真时间 |
| 数据源 | `POST /api/v1/simulate/start|stop|pause|resume|speed|step`；`GET /api/v1/simulate/status` |
| 亮点 | **路网选择器**：内置列表（雄安 base_network / 随机网格 / 蜘蛛网等 3-5 个），一键换路网启动 → 直接展示"**路网无关模型**"：同一个 agnostic 权重、换路网不重训照样控灯 |

### B. 路网可视化画布（P0，主视觉）

| 项 | 说明 |
|---|---|
| 作用 | 全场视觉中心，展示"车流 + 信号 + 协同调控"实时发生 |
| 底图 | MapLibre GL（离线矢量瓦片，容东片区），路网边按 GeoJSON `GET /api/v1/network` 叠加 |
| 车辆层 | deck.gl instanced 渲染，增量更新（WS `vehicle_update`），按类型着色：passenger 蓝 / bus 红 / fleet 橙 / truck 紫 / bicycle 绿 |
| 信号灯层 | 交叉口绘制相位指示圆点，颜色=信号态（绿 G / 黄 y / 红 r），WS `tls_update`；**切到 MAPPO 后相位切换肉眼可见加快/更合理** → 这是"AI 在控灯"的直接证据 |
| 排队热力 | 边着色按排队长度（`edge.queue`），拥堵蔓延直观 → 切算法后热力消退 = 效果对比 |
| 事件标记 | 事故/施工图标（`/events/list`），点击看详情 |
| 交互 | 点击路口 → 详情卡：当前相位/相位时长/排队/控制模式（MAPPO or SCOOT） |
| 数据源 | WS `/ws`：`vehicle_update`、`tls_update`、`metrics_update`、`simulation_event`；可选 `set_viewport` 视域裁剪 |

### C. LLM Agent 对话面板（P0 ⭐，本次重点）

| 项 | 说明 |
|---|---|
| 作用 | 直接对应赛道 C 补充要求"LLM Agent"，也是全场最抓眼的交互 |
| 对话框 | 输入框 + 发送按钮；回车发送；发送后显示"**Agent 正在分析态势…**"加载态（当前接口为同步返回，多步工具调用需 5-20 秒，务必有 loading，禁止假打字机） |
| 消息流 | 用户气泡 / 助手气泡（Markdown 渲染，报告类回复可渲染标题与列表） |
| **工具调用回放** | 每条助手消息下方折叠展示本次调用的工具：`🔧 plan_route({"from_edge":"E21_1","to_edge":"E9_19"}) → 路线 [E21_1→…→E9_19]，78s`。**这是"Agent 真的在干活"的可视化证明，必做** |
| 快捷指令 chips | 三场景示例指令一键填充：①"检测到 E21_1 附近突发车流，请分析现状并给出应急调控建议" ②"我想从 E21_1 去 E9_19，请规划最优路径并给出驾驶建议" ③"请巡检全局路网，如发现拥堵请给出协调建议并执行" |
| 状态指示 | 顶栏或面板头部：当前模型 `qwen2.5:3b`、协议 text-json、9 个工具（`GET /api/v1/agent/status`） |
| 数据源 | `POST /api/v1/agent/chat {"message": ...}` → `{reply, tool_calls[]}`；未启动仿真时后端返回"请先启动仿真"提示，前端在对话区直接展示即可（本身就是演示点） |
| 进阶（可选） | 把"Agent 刚执行的操作"高亮到画布上：如 plan_route 的路线在地图上划线、set_params 在信号灯层闪烁 → "对话与仿真联动"终极效果 |

### D. 实时指标面板（P0）

- 四张数据卡：在网车辆 / 平均速度 / 平均等待 / 平均排队（`GET /api/v1/metrics/realtime` + WS `metrics_update` 每 60 步）
- ECharts 时间序列：avg_speed / avg_delay / queue_length（`GET /api/v1/metrics/history`），**对比曲线放 G 区**
- 数字变化动画（+/- 着色），突出"切换方案后指标立刻改善"

### E. 方案管理面板（P0）

| 方案 | 面板内容 |
|---|---|
| scheme_1 固定配时 | 时段方案列表、绿波走廊开关（`/schemes/1/config`） |
| **scheme_2 MAPPO/SCOOT** | 模式切换按钮（MAPPO / SCOOT / AUTO）；参数滑块 min_green / max_green / switch_clearance（`set_params`）；当前权重显示（legacy / agnostic） |
| scheme_3 车端引导 | 车队注册、重路由触发、禁行区（`/schemes/3/config`） |
| 通用 | 方案状态（`/schemes/{id}/status`）；**同路网同场景一键对比**（见 G） |

### F. 事件注入面板（P1）

- 三个一键按钮：注入事故（accident）/ 施工（construction）/ 突发车流（large_event），选择受影响边（可点画布选边）
- 事件列表 + 时间线（`/events/list`）
- **联动彩蛋**：注入后自动向 Agent 发"检测到 XX 事故，请给出应急调控建议"，让观众看到 Agent 读事件 → 分析 → 调参 → 总结的完整闭环

### G. 对比分析区（P1 ⭐，数据说服力所在）

- 同路网同场景下，三方案 + 固定配时的实时曲线叠加（avg_speed / avg_delay / queue_length）
- 汇总表：行程时间 / 平均等待 / 排队 / 通过车辆数（对接评估脚本输出或 `/metrics/history`）
- 一键"截图导出"（答辩 PPT 素材）
- 说明文案：实测数据（如 routes_clean700 场景：MAPPO 通过 49 辆 vs SCOOT 63.5 辆，等待 45s vs 60s；agnostic 在未训练路网上仍优于固定配时）——**写真实数据，别夸大成假数据**

### H. 模型部署信息卡（P2，可选模态框）

- ONNX 边缘推理：模型体积（fp32 82.5KB / int8 24.9KB）、单次推理时延（7.4μs / batch64 0.030ms）、与 PyTorch 输出一致率（99.4%@int8）
- 路网无关说明卡：一张图讲清"18 维固定观测 → 任意网格路网直接用"

## 4. 关键演示流程（前端要能支撑这三条线）

| 流程 | 操作 | 画面要点 |
|---|---|---|
| ① AI 控灯改善 | 启动 → 固定配时跑 60s（拥堵蔓延、热力变红）→ 切 scheme_2 MAPPO（热力消退、速度回升）→ 对比曲线上升 | 信号灯层 + 排队热力 + G 区曲线 |
| ② Agent 对话 | 快捷指令②"规划路径" → 对话框出现工具调用回放（plan_route 真实路线）→ 助手回复驾驶建议 | C 区回放折叠展开 |
| ③ 应急响应闭环 | 点"注入事故" → 事件标记出现 → 一键让 Agent 响应 → Agent 调 set_params/switch_mode → 指标恢复 | F 区 + C 区 + 画布联动 |

## 5. 技术实现要点

- **框架**：沿用《前端规范.md》Vue 3 + Vite + MapLibre GL + deck.gl + ECharts；对话面板用普通组件即可，无需额外库（Markdown 渲染可选 marked）
- **通信**：Fetch 走 REST，`/ws` 用原生 WebSocket；建议封装 `useApi()` / `useWs()` composable
- **Agent 请求注意**：`/agent/chat` 为同步返回，前端必须给 loading 态并禁用重复提交；可加"停止"按钮（后端暂不支持中断，先做禁用即可）
- **状态管理**：Pinia——`simState`（仿真/方案/步数）、`metricsState`（实时+历史）、`agentState`（对话记录+工具回放）、`eventState`（事件列表）
- **目录建议**：
  ```
  src/
  ├── views/        Dashboard.vue,  CompareReport.vue(可选)
  ├── components/
  │   ├── sim/       ControlBar.vue, NetworkCanvas.vue, VehicleLayer.vue, TlsLayer.vue
  │   ├── agent/     ChatPanel.vue, ToolCallLog.vue, QuickPrompts.vue
  │   ├── metrics/   MetricCards.vue, TimeSeriesChart.vue
  │   ├── scheme/    SchemePanel.vue, ParamSlider.vue
  │   └── events/    EventInjector.vue, EventLog.vue
  └── composables/   useApi.ts, useWs.ts, useAgent.ts
  ```
- **性能**：车辆 3000+ 用 deck.gl instanced + WS 增量；视域裁剪 `set_viewport`；图表下采样（interval 参数）

## 6. 实施优先级（按答辩收益排序）

| 优先级 | 元件 | 理由 |
|---|---|---|
| **P0 必做** | 仿真控制条 + 路网选择器 | 演示入口 + 展示路网无关 |
| **P0 必做** | 路网可视化画布（车辆/信号/排队热力） | 主视觉，AI 控灯证据 |
| **P0 必做** | **Agent 对话面板（含工具回放）** | 赛道 C 硬性要求，全场亮点 |
| **P0 必做** | 实时指标卡片 + 方案管理面板 | 支撑流程①② |
| **P1 加分** | 对比分析区（三方案曲线+汇总） | 数据说服力 |
| **P1 加分** | 事件注入面板 + Agent 联动 | 流程③，互动性强 |
| **P2 可选** | 模型部署信息卡 / 对比报告页 / 路线画线联动 | 锦上添花 |

> 建议排期：P0 一屏 Dashboard 约 3-5 人日（画布复用 deck.gl 模板）；P1 约 2-3 人日；P2 视时间。
