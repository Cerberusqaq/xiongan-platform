# 演示视频录制脚本与操作说明（5–8 分钟）

> 适用：**XH-202613 车路云一体化协同管控平台（雄安·城市大脑）**
> 按时间轴照做即可，含每步操作位置、画面应长什么样、可照念的旁白稿、注意事项与兜底方案。
> 录制前请先通读一遍全文档，并在正式录之前**按"彩排清单"完整走一遍**。

---

## 0. 一句话项目定位（你先理解我们在演示什么）

我们做了一个 **"雄安城市大脑"交通仿真平台**：用 SUMO 微观仿真搭出一个 **20 个信号路口的"窄路密网"片区**，把**官方提供的 20 个真实路口配时（早/平/晚三档 Excel）**完整重建进去；平台里实现了三套可切换的信号/引导算法 + 一个 **LLM 智能体（AI 协管员）**，可以像聊天一样让 AI 去观察拥堵、调整信号灯、再对比调前调后的效果。赛题要求这段视频证明"**场景导入 → 算法部署 → 实时协同调控 → 效果对比**"全流程，并让关键指标实时显示在画面里。

## 1. 录制前准备（务必先做）

### 1.1 环境与画面

| 项目 | 要求 |
| --- | --- |
| 浏览器 | Chrome/Edge 最新版，**全屏**（建议 F11），分辨率建议 1920×1080，系统缩放 100% |
| 页面地址 | 前端 `http://localhost:5173`（本机已启动），或双击项目根目录 `start.bat` |
| 主题 | **保持默认深色主题**（不要切浅色）——更符合"城市大脑指挥中心"观感 |
| 录音 | 独立麦克风，先试录 10 秒检查音量；语速放慢 |
| 录屏软件 | OBS / Windows 自带 Win+G，帧率 30fps 即可 |
| 片头素材 | 可选：项目标题文字页（可后期加字幕代替） |

### 1.2 功能自检（录制前 5 分钟在页面完成）

打开页面后系统会**自动启动**：base_network（20 路口）+ 平峰车流 + 官方方案（mappo优化），顶栏倍速显示 **5×**。请确认：

1. 顶部左中可见 `车路云协同管控平台`；方案区显示「当前：官方方案 · AUTO 自动」（或类似）；右侧状态灯为绿色"运行中"，并有步数/仿真时间。
2. 画布上出现灰色路网和流动的彩色小方块（车辆），**若画布仍空白，是 90 秒预热期，再等 10–30 秒**。
3. 左侧（默认左栏"指标"页签）有卡片：在网车辆、平均速度、平均等待、平均排队，及完成率/最堵塞道路/最堵塞路口等。
4. 页面底部有"方案对比"条：一条绿色**实时曲线（平均速度）**、一个"综合评分"框。
5. 右侧为 **Traffic Copilot · 智能体**：下方有"LLM 模型"下拉与"建议指令"按钮。

> ⚠️ **LLM 可用性检查（最重要）**：在智能体下方"LLM 模型"下拉里，若**有可选模型** → 主线 A（含 AI 对话）。
> 若**下拉为空 / 发送后报错** → 说明后端没配模型，不要卡住，改用 **主线 B（纯手动对比）**（见 §6）。
> 判断方法：在输入框输入"你好"回车，AI 有文字回复即 OK。

### 1.3 术语速查（旁白可能用到，意思别讲错）

- **SUMO**：微观交通仿真引擎（每个路口、每辆车都在模拟真实规则）。
- **base_network / 20 路口**：平台内置的代表"雄安窄路密网"的片区路网。
- **官方配时**：赛题提供的 20 个真实路口早/平/晚三档信号配时（Excel），我们转成了仿真可用的相位程序。
- **方案一**：经典定时配时 + Webster 最优配时 + 主干道"绿波"协调。
- **方案二**：MAPPO（多路口强化学习）或 SCOOT（规则自适应），每 5 秒根据排队自适应换灯；AI 的核心。
- **方案三**：车端引导——给车队重新规划路径、避开拥堵/禁行。
- **基线 / 固定配时**：固定不动时的对照组。
- **Agent / 智能体 / Traffic Copilot**：接入大模型的"AI 协管员"，能调用工具看数据、改参数、对比效果。
- **实时指标**：左侧卡片（在网车辆/平均速度/平均等待/平均排队…）；**完成率**=已到达÷已出发。
- **排队/LOS**：路口进口道排队的车数；LOS 是服务等级（A 最畅通→F 最堵）。

### 第一幕 0:35–1:50 —— 真实场景导入与高保真仿真

**目标**：证明"场景构建/导入 + 可编程场景 + 数据可视化"（对应赛题"高保真可编程仿真场景生成工具"）。

**操作序列（慢速演示）**：

1. **路网下拉**：点击顶栏左侧路网下拉按钮（显示"base_network ▾"）→ 列表内可见"内置路网"，悬停任一名字会弹出灰色 SVG 小预览图。→ 点回 **base_network**。
   - 画面说明：画布展示一个网格状 20 路口片区；左上角小字显示路网名与"xx 边 · xx 节点 · xx 车辆"。
2. **框选放大一个路口看细节**：在画布上用**滚轮**放大到某一个十字路口（不必精确），再**双击画布**可复位全图（演示后复位）。
   - 放大后能看到：带箭头的信号灯、排队车辆、双向道路中央双黄线。
3. **场景体系口播展示**：指着画布右上角的"交通场景"下拉（运行中为灰色禁用，镜头示意即可）：当前为"平峰 · 中流量"，它提供深夜/平峰/高峰/极高峰/区域热点等多档。真正的切换演示放在第二幕"停止后"一起做（见下）。
4. **点击对象看数据**（最能体现"数据可视化"）：
   - **点一辆车**（画布上任意移动的小方块）→ 弹出信息卡：类型/速度/车道/累计等待/路线，若有"驾驶建议"一并展示（建议车速+理由）。
   - 关闭卡片；**点一个路口节点**（信号灯所在圆点）→ 信息卡显示：排队车辆、平均等待、通过车辆、当前相位与时长。
   - 关闭卡片；**点一条道路**（一条灰色路段）→ 显示车道数/限速/在网车辆/平均速度/占有率；信息卡里还有"在此边添加车流"按钮（可点一次：输入 5 辆车→"在此边添加车流"，观察路上多出几辆车）。
5. 双击画布复位全图。

**旁白稿（约 60–70 秒）**：
> "平台内置了雄安特色的高保真路网——这是 20 个信号路口组成的'窄路密网'片区。我们放大到单个路口，可以看到逐车道绘制的真实几何、逐方向带箭头的信号灯，以及排队中的车辆。右上角可以配置不同峰期场景：从深夜低流量到高峰高流量，还有'区域热点'——让路网中心局部饱和、排队外溢、外围畅通，这正是考验协调算法的典型场景。画布上的一切都是可交互的真实仿真数据：点一辆车，能看到它的类型、车速、累计等待和驾驶建议；点一个路口，能看到排队、平均等待、当前放行的相位；点一条道路，能看到限速、占有率和实时车流——我们还可以直接在这一条路上临时加车。也就是说，仿真环境是'高保真、可编程、可交互'的。"

**口径提醒**：说"20 个信号路口"不要说错成"20 条路"。

### 第二幕 1:50–3:10 —— 算法体系与官方配时库接入

**目标**：交代平台的三套算法 + "官方 20 路口真实配时"数据资产如何接入（对应赛题"算法框架 + 场景适配"）。

**操作序列**：
1. 先点顶栏 **停止**（若在运行）。
2. **方案下拉**位于顶栏（启动前显示为"方案"下拉框）。依次点开并**只读列表**（不启动）：`方案一 · 固定配时+绿波` / `方案二 · MAPPO/SCOOT` / `方案三 · 车端引导` / `官方方案 · mappo优化（20路口）` / `基线 · 固定配时`，每项停留 1 秒让字幕跟上。
3. 选回 **官方方案 · mappo优化（20路口）**，场景右上角选回 **平峰 · 中流量**，点顶栏 **启动仿真**。
4. 运行后：顶栏方案区变灰字徽标「当前：官方方案 · AUTO 自动」。等画布出现车辆。
5. 打开左侧页签 **方案**（面板标题"控制方案"）：能看到"方案一/方案二/方案三"三个小页签，可点开方案二页签展示 MAPPO/SCOOT/AUTO 与滑杆参数（**只展示不点击**，因为当前不是方案二）。
6. 打开左侧页签 **事件**（面板标题"扰动与车辆"）：展示"事故限速/施工占道/突发车流"三个按钮和"生成车流/加入车辆"，说明平台支持"扰动注入"（先不点）。

**旁白稿（约 70 秒）**：
> "平台在算法侧提供三套可运行、可切换的控制方案：方案一是经典交通工程——分时配时加 Webster 最优配时，并支持主干道绿波协调；方案二是我们的 AI 核心——MAPPO 多路口强化学习，每 5 秒根据各进口排队自适应调整绿灯，权重不可用时自动降级为 SCOOT 规则自适应；方案三是车端协同——给注册车队动态重路由，绕开拥堵和禁行区。更重要的是，我们把赛题官方提供的 **20 个真实路口的早/平/晚三档配时**逐相位重建成了 SUMO 相位程序——这就是顶栏的'官方方案·mappo优化'：运行时它会按实时东西/南北排队比，在这三档官方配时之间自动换挡，相当于把真实工程配时库装进了仿真。平台上还保留了事故、施工、突发车流等扰动注入能力，为算法提供'数字靶场'。"

**口径提醒**：MAPPO 说成"多路口强化学习"即可；不要展开"PPO/CTDE"等名词。官方配时三档=早高峰/平峰/晚高峰。

### 第三幕 3:10–4:50 —— 实时协同调控（核心演示）

**目标**：展示"高峰拥堵 → 实时观测 → AI 决策 → 信号调整 → 路网疏解"，是全片最精彩、也是赛题最看重的"从算法部署到实时协同调控"。

**推荐路径（主线 A：智能体可用时）**

**3A-1 制造一个有说服力的拥堵（约 40 秒）**
1. 顶栏点 **停止**。
2. 右上角场景切到 **高峰 · 高流量**（或"区域热点 · 局部拥堵"），顶栏方案选 **方案二 · MAPPO/SCOOT**，点 **启动仿真**。
   - 目的：高峰/热点下会自然出现排队，MAPPO/SCOOT 能展示实时自适应的价值。
   - ⚠️ **注意**：主线 A 这一段用"方案二"，而不是默认的"官方方案"——Agent 的"调整信号参数/切换模式"等工具主要作用于方案二；顶栏运行时徽标应显示「当前：方案二 · AUTO 自动」（或 SCOOT/MAPPO），口播前先核对该徽标。
3. 等待车辆出现并让画面跑 20–30 秒，找到一处明显的排队（放大镜头对准它）。
4. 可再加一点压力：左侧页签 **事件** → "生成车流"区选 **全入口** → 数量 30–50 → 点 **生成**；或点 **突发车流**（在目标道路附近注入一批车）。画面上对应道路会出现彩色高亮/事件圆点，左上角出现图例（事故/施工/突发车流）。

**3A-2 请 AI 协管员处理（约 50 秒）**
1. 右侧 **Traffic Copilot** 面板：在底部输入框输入（或用"建议指令"随机到相近的再点发送）：
   `请巡检全局路网，找出拥堵区域并给出协调建议`
   或直接更明确：
   `东侧拥堵，请调整最长绿灯并对比前后效果`
2. 回车发送 → 画面出现 AI"正在分析态势并调用工具…"，随后逐条展开它调用的**工具卡片**（工具名 + 参数 + 成功/失败），包括：查看路口/道路数据 → 切换方案/调参数（`configure_algorithm` 之类）→ **前后对比（compare_metrics）**。
3. 在 AI 输出的对话气泡里，应能看到它对"调控前后指标"的文字总结（如排队/速度变化）。
   - ⚠️ AI 回复是模型生成的，**每一条文字不可控**；请只要求画面出现"工具调用链条 + 成功"与大致趋势即可，具体数值以左下角实时曲线为准。若 AI 一次没说对比，可再补发一条建议指令："请对比调控前后的指标并总结效果"。

**3A-3 画面与数据验证（约 30 秒）**
1. 把镜头拉回拥堵路口，观察排队随绿灯变短。
2. 指着左侧"指标"面板的实时卡片与底部"实时曲线·平均速度"说：曲线回升说明路网正在被疏通。

**兜底（主线 B：智能体不可用时）** 直接跳到 **§6 主线 B**，画面效果接近，只是由人点按钮代替 AI。

**旁白稿（约 90 秒，主线 A 版）**：
> "接下来我们演示'实时协同调控'。先把场景切到高峰，并注入一批突发车流，让路网出现真实的拥堵排队——你可以看到这一片路口已经排起长队、上方出现突发车流的事件标记。现在我不去手动调灯，而是让平台的 AI 协管员来处理：我下达指令'请巡检全局路网，找出拥堵区域并给出协调建议'。可以看到，AI 正在分析态势并调用工具——它先读取全局与路口的实时数据，定位到最堵的道路和路口；随后调整信号控制参数、切换更合适的运行模式；最后调用前后对比工具，把调控前后的指标放在一起比较。随着绿灯分配被重新优化，大家可以看左侧指标和底部平均速度曲线——排队在回落、平均速度在回升，拥堵正在被逐步疏解。这就构成了'感知—决策—执行—验证'的完整闭环。"

**口径提醒**：不要说"AI 一定把路网变畅通/数字一定变大"——极端高峰可能改善有限；请说"排队回落/速度回升"这类画面可见事实，或"趋势好转"。**先看画面再念**，避免口型与数值对不上（后期可剪辑对齐）。

### 第四幕 4:50–6:20 —— 效果对比与量化

**目标**：展示量化对比、评分、报告生成（对应赛题"评估体系与报告"）。

**操作序列**：
1. 保持运行，把镜头对准**底部"方案对比"区**（可稍拉高底部：把鼠标移到"方案对比"标题条上方的小横条，按住上下拖动）。
   - 显示：**实时曲线 · 平均速度**；若需离线对比柱状图，可在"设置"里打开"显示离线评估图表"（设置按钮在顶栏右侧）。
   - 显示**综合评分**框（效率/稳定/公平三项子分）。若显示"硬性筛选未通过"也正常——说明当前太堵/不满足评分前提，可把画面切到"平均等待/平均排队"解释；**不要在镜头前纠结**。
2. （可选）点"方案对比"右上角 **⛶ 全屏数据**：弹出完整数据面板（全局指标 + 各路口 LOS + 历史 + 事件），停留 3–5 秒后关闭。

## 5. 录制最容易翻车的点（务必注意）

| 风险 | 现象 | 处理 |
| --- | --- | --- |
| 预热期空白 | 启动后画布暂时没车 | 别慌，等它自己出车；不要对着空白画面念太久（可先切别的镜头） |
| LLM 不可用 | 智能体发送后报错/转圈 | 立刻改走 **主线 B（§6）**，画面无缝衔接 |
| 数值与口播对不上 | 你说"速度回升"但曲线没动 | 先看画面再念；后期剪辑可把口播和曲线高潮对齐 |
| Agent 回复内容飘 | AI 文字与画面不符 | 只强调"工具调用成功 + 前后对比存在"，具体结论照画面讲 |
| 忘了当前方案 | 口播说方案 A 实际跑 B | 每次切完先看顶栏徽标再开口 |
| 误点运行中禁用的控件 | 按钮灰色点不动 | 属正常，说明该操作需停止后重开 |
| 弹出"硬性筛选未通过" | 评分框红色提示 | 不要念具体原因，切画面到指标卡即可；或降低场景负荷重录该段 |
| 不小心退出全屏 | 画面缺一块 | Win+G/OBS 都能暂停，整理好再继续，后期可剪 |

## 6. 剪辑建议（后期 30–60 分钟）

1. 总时长控制在 **6:30–7:30**；超出的段落优先删"方案逐条介绍"的停顿。
2. 每幕之间 0.5 秒黑场；关键指标处可加**局部放大/慢放**，并在画面上叠大字标注（如"排队 ↓""平均速度 ↑"）——赛题明确要求"关键数据指标实时叠加显示"，画面里已常驻指标卡，建议再叠文字强化。
3. 全程加中文字幕（尤其口播术语）。
4. 片头 5 秒标题页可自做（Canva/PPT 导出 PNG 即可）。
5. 若某段数值没录好，可补录"口播"后接画面，不必整段重来。
6. 导出格式：MP4/H.264，1080p，码率 ≥8Mbps。
